# THE RAVEN 阅读室 v4.2

这是一份基于现有 v4 / v4.1 阅读室的增量更新。包含这次的书架、剪纸钥匙、藏书仓库同步代码和说明。它不是整个网站仓库。

## 这次完成的调整

1. 书架内侧的顶端增加固定的柔和投影。无论停在哪一行、怎样上下滚动，阴影都留在顶端。
2. 重新划定书架的滚动区域。最下面层板的边缘、支撑花角和阴影都在同一个滚动内容中，不再有一栏留在原地。空书架和少量藏书也会补齐背景。
3. 钥匙改成哑光彩纸叠层，绳环与流苏也采用纸片质感。钥匙在整张书库画面里重新生成，停留时没有贴纸边缘。鼠标移上去时，流苏轻轻摆动，不拉扯整张背景。
4. EPUB 导入后先保留本机副本，再写入配置的藏书仓库。新写入必须收到真实提交回执，才能显示已经入藏。
5. 网络失败时保留待同步记录。重新连接、网络恢复或回到页面后可以继续。同内容重试会核对仓库文件，不重复提交。
6. 其他设备可以读取同一份仓库书目、封面和 EPUB。书籍会留在仓库中，直到你主动删除或修改仓库内容。
7. 旧本机导入书同步后不会在刷新时重复上架。原来的本机阅读链接、阅读位置和本机缓存仍可继续使用。

## 目前的接入状态

网页与服务端代码已经完成，也通过了模拟 GitHub 的自动验证。**本更新包没有部署上传服务，没有配置真实仓库写入身份，也没有产生任何真实远程提交。**

仅覆盖网页文件，视觉修正会生效，但跨设备上传还不会生效。需要按下面步骤部署服务。服务尚未连接时，画面会明确显示书暂存本机，不会把它说成已经保存到仓库。

## 给本地 agent 的安装步骤

1. 把 `网站覆盖文件` 中的内容合并到现有网站根目录。应得到 `reader-room` 与 `library-sync-server` 两个同级目录。按文件覆盖，不要用整个目录替换现有项目。
2. 保留现有其他文件，尤其是城市数据、上海附近城市素材、`data/books`、`reader-room/data/catalog.json`、字体、旧阅读器图片和现有 EPUB。这个更新包没有包含它们，也不需要删除它们。
3. `reader-room/config.js` 增加了 `repositorySync.endpoint`。如果本地已经修改主页地址或书目地址，请把这一项合并进去，并保留本地地址设置。不要改变 `storageKey`、`legacyStorageKey`。
4. 在现有本地站点打开 `reader-room/index.html`。向下滚动到最后一行，检查固定顶端阴影、一起移动的末层层板与剪纸钥匙。
5. 部署下面的仓库同步服务后，再进行一次真实上传和另一设备验证。

本包包含 v4.1 的 `epub-import.js`，用于保留正常 EPUB、Mac `.epub` 文件夹包和外层 ZIP 的兼容修复。导入失败与仓库连接失败会分开显示。

## 接通藏书仓库

服务的完整文档在 `网站覆盖文件/library-sync-server/README.md`。

当前源码中的书源是 `StellaWQL/recipes-widget` 仓库的 `practice` 分支，目录为 `data/books`。当前文件没有确认一个独立 subrepo 的配置。如果你的本地项目已经把藏书移到另一仓库，请在服务端 `.env` 或托管平台环境变量中填写真实的 `GITHUB_OWNER`、`GITHUB_REPO`、`GITHUB_BRANCH`、`GITHUB_BOOKS_PATH`。

### 服务端

在支持长期 Node.js 进程的环境部署 `library-sync-server`，保留与它同级的 `reader-room/vendor/jszip.min.js` 及许可证。不需要安装 npm 依赖。

- `GITHUB_TOKEN` 只放在服务端私有环境变量中，给它目标藏书仓库的 Contents 读写权限。
- `LIBRARY_UPLOAD_KEY` 使用单独生成的随机密钥，至少 32 个字符。它是收书画面的书库钥印，不是 GitHub token。
- `ALLOWED_ORIGINS` 填网站的明确来源地址，可以填写多个来源。每项只含协议、主机与端口，不含页面路径。
- 默认一次可接收 25 MiB。环境变量可以调整上限。
- 真实 `.env` 不提交。包内只有不含凭据的 `.env.example`。

服务文档提供本地启动、HTTPS 部署和接口说明。GitHub Pages 只托管静态网页，不能直接运行这个 Node 服务。已有网站可以继续放在 Pages，上传服务另行部署。

### 网页

如果 `/api/library/` 已反向代理到网页的同一来源，保留 `repositorySync.endpoint` 默认值。

如果使用独立服务，把它改为服务的完整地址，例如 `https://你的服务域名/api/library/`。收书画面只输入书库钥印，不输入服务器地址或 GitHub token。

连接后，当前设备过去暂存的书也会进入同步队列。其他设备连接同一服务后会读取相同书目。钥印只保存在当前会话中。原来公开书源中的书仍可按原方式读取。

### 实际上线验收

1. 上传一本 EPUB。确认界面完成入藏，GitHub 的目标分支确实出现该文件及提交。
2. 在另一浏览器或另一设备连接同一书库。确认能看到原封面并打开正文。
3. 再上传相同文件，确认没有重复增加藏书或提交。
4. 断网导入一本书。应保留本机可读副本，显示等待同步，恢复连接后继续。

本轮同步的是书籍文件与书目。阅读进度仍按现有方式保存在各设备中，没有新增跨设备进度同步。

## 文件范围

`reader-room` 下的改动包括书架样式、整图素材、物件动画、导入流程、仓库客户端、配置和入口。同步服务是新增目录。完整文件与 SHA-256 清单见 `文件清单.json`。

没有改动主页的水果、台阶、鸽子、牌盒、城市内容，也没有替换原书封面。阅读器保留双页、窄屏卷轴、旧玫瑰色字体及既有字号设置。
